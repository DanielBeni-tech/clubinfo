# TRD — Technical Requirements Document

## Site officiel du Club Informatique SUP'PTIC

---

## 1. Choix de stack

| Composant          | Choix recommandé                                                                                         | Justification                                                                                                                                          |
| ------------------ | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Framework          | **Next.js (App Router)**, export statique                                                                | Fidèle à l'architecture du site de référence clubgi-enspy.com ; composants réutilisables ; bon SEO ; prépare une V2 dynamique sans réécriture complète |
| Styling            | **Tailwind CSS**                                                                                         | Rapide à mettre en œuvre, cohérent, facile à maintenir entre promotions d'étudiants                                                                    |
| Contenu            | **Fichiers JSON/Markdown versionnés dans le repo** (voir Backend Schema)                                 | Pas de CMS ni de base de données requis pour la V1 ; tout est modifiable via Git                                                                       |
| Icônes             | Bibliothèque d'icônes libre (ex. Lucide)                                                                 | Pour les 6 cartes "domaines d'expertise" et les éléments d'UI                                                                                          |
| i18n (préparation) | Dossiers de contenu structurés `content/fr/...` et `content/en/...` dès la V1, mais seul `fr` est rempli | Permet d'activer l'anglais plus tard sans refonte de l'architecture                                                                                    |

> Si l'équipe du Pôle Développement débute en React, une alternative HTML/CSS/JS + Tailwind (sans framework) est possible pour livrer plus vite, avec migration vers Next.js en V2. Cette option dégrade cependant la préparation au bilingue et la réutilisation de composants (fiches projets, cartes domaines).

## 2. Hébergement

| Solution                | Avantages                                                                                                        | Limites                                                                                           |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **Vercel** (recommandé) | Intégration native Next.js, déploiement automatique à chaque push Git, HTTPS gratuit, sous-domaine `.vercel.app` | Limites du plan gratuit sur la bande passante (largement suffisantes pour ce trafic)              |
| Cloudflare Pages        | Très bon CDN, gratuit, déploiement Git                                                                           | Configuration Next.js légèrement plus manuelle                                                    |
| GitHub Pages            | Simplicité maximale                                                                                              | Moins adapté à Next.js en mode non-purement-statique (export requis, pas de fonctions serverless) |

**Recommandation** : Vercel en V1, pour le déploiement automatique et la simplicité de configuration Next.js. Nom de domaine propre (ex. `.cm`) à budgétiser pour une V2 ; en attendant, sous-domaine gratuit type `club-info-supptic.vercel.app`.

## 3. Gestion des formulaires (sans base de données)

- Service de formulaire gratuit : **Web3Forms** ou **Formspree**.
- Chaque soumission (adhésion ou contact) déclenche :
  1. Un e-mail de notification vers l'adresse du Club / Pôle Communication.
  2. Un e-mail de confirmation automatique à l'expéditeur.
  3. L'ajout d'une ligne dans un Google Sheets partagé (via l'intégration du service ou Google Apps Script).
- Anti-spam : champ honeypot invisible + limite de fréquence ; reCAPTCHA v3 gratuit en renfort si nécessaire.

## 4. Gestion des médias (galerie, vidéos, images projets)

- Images optimisées via `next/image` (redimensionnement, formats modernes WebP/AVIF automatiques).
- Photos de la galerie et des projets stockées dans le repo (`/public/images/...`) ou sur un CDN d'images gratuit (ex. Cloudinary plan gratuit) si le volume devient trop lourd pour Git.
- Vidéos/démonstrations : **jamais hébergées directement** sur le site — intégrées par embed YouTube/Vimeo pour ne pas consommer de bande passante ni de stockage.
- Galerie avec lightbox léger (bibliothèque JS légère, ex. `yet-another-react-lightbox`).

## 6. Performance, SEO, accessibilité

- Score Lighthouse cible : 90+ (Performance, Accessibilité, SEO, Bonnes pratiques).
- Balises meta (titre + description) et image Open Graph par page.
- `sitemap.xml` et `robots.txt` générés automatiquement par Next.js.
- Attributs `alt` descriptifs sur toutes les images (galerie comprise).
- Contraste conforme WCAG AA, navigation clavier fonctionnelle sur les CTA et formulaires.

## 7. Sécurité

- HTTPS forcé (automatique sur Vercel).
- Aucune donnée sensible stockée côté site (pas de mot de passe ni paiement en V1).
- Validation des champs de formulaire côté client et côté service tiers.
- Dépendances npm maintenues à jour (`npm audit` en CI si possible).

## 8. Déploiement / CI-CD

- Dépôt Git sur GitHub, organisation ou compte du Club (continuité entre promotions).
- Déploiement automatique à chaque `push` sur la branche `main` via l'intégration Git de Vercel.
- Branches de fonctionnalités (`feature/...`) avec prévisualisation automatique (Vercel Preview Deployments) avant fusion.

## 9. Compatibilité

Support des deux dernières versions de Chrome, Firefox, Safari, Edge, ainsi que Chrome Mobile et Safari iOS — cohérent avec un public majoritairement mobile.
